What it does

Receive & roll

Listens on UDP 514, splits Omada's multi-record datagrams into one line each (receive time + sender + raw payload), and keeps a 50 MB rolling raw log — newest events always survive, oldest roll off. Runs headless from boot as a per-user scheduled task.

Search event history

A local SQLite index keeps searchable per-event records, including observed DHCP address allocations and other activity. Its default 500 MiB retention target is separate from the 50 MB raw log; DHCP observations are historical records, not a current lease table.

Condense the firehose

Every record is tallied at ingestion: flows fold into src → dst/proto/port counts with first/last seen and the 20 most recent occurrence timestamps; repeated alerts fold into message templates. Tallies persist across restarts; recovery resumes from the saved raw-log checkpoint when it is still present.

Visualize live

An interactive scatterplot, on localhost by default: swappable X/Y axes, color and size encodings, log scale, RFC1918 direction slicing (internal / outbound / inbound / other), drag-to-zoom on any region, per-group aggregate sizing, pattern spotlight — click any dot to grey the noise and pop its related traffic — color-key drilldown (click a legend entry to filter to it), a scoped stats panel (unique counts + direction breakdown reflecting whatever you've spotlighted or zoomed into), smart IP filters (ranges, shorthand lists, CIDR), and built-in hover help on every control. Auto-refreshes without disturbing your view.

Traffic sliced by direction — internal vs outbound at a glance; an inbound lane appears whenever external-to-LAN flows are logged.

Drag to zoom — brush any region and dense clusters become readable; double-click or Esc zooms back out.

Pattern spotlight — click any dot to grey the noise and pop its related traffic: the same conversation (white-ringed), the same host pair, the same service.

Quickstart

For the recommended no-Git install, get the versioned Windows ZIP asset from the latest GitHub release (for v1.4.0, Omada-Logger-Viz-v1.4.0-windows.zip), then use File Explorer's Extract All. Open PowerShell in the extracted project folder. For Git, use the optional clone commands below. Keep the extracted folder in place after installation; the scheduled tasks use its path.

# Windows 10/11, Python 3.8+ code target (tested with Python 3.14.6)
python --version

# Optional Git install (skip these two commands for the ZIP):
git clone https://github.com/Treystu/Omada-Logger-Viz.git
Set-Location Omada-Logger-Viz
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\install.ps1        # one UAC prompt: firewall rule + boot task + watchdog

# Omada Controller: Logs > Setting > Advanced > Remote Logging
#   Enable, point to this PC's LAN IP, port 514, More Detail Logs on

# Default: hidden dashboard server starts at logon; click the desktop
# shortcut to open the browser. Optional boot-start server:
.\install.ps1 -VizBoot

The default receiver allowlist and firewall rule accept UDP 514 from 192.168.0.0/24. If your LAN uses another subnet, update both the receiver --allow setting and the firewall rule. The dashboard data folder is %LOCALAPPDATA%\OmadaSyslog; the index begins a backfill from raw lines still retained on first use.

FAQ

Is there really no cost and no catch?

It is MIT-licensed open source: free to use, inspect, modify, and redistribute. No signup, no telemetry, no paid tier. Donations are optional and voluntary.

Does it work with syslog senders other than TP-Link Omada?

Yes — it listens on standard UDP 514 and accepts any RFC3164-style sender. The flow-tally condensing is tuned for Omada's log format; other devices still record fully and tally by message template.

Where does my data go?

By default, the raw log, tallies, and searchable event index stay in your local AppData; no telemetry is sent. The dashboard binds to localhost by default. If you deliberately serve the chart to your LAN, its API redacts message bodies, but templates may still contain identifying information. Event search and full raw-event views remain local-only.

Why UDP only — and why Windows only?

TP-Link Omada devices expose remote logging over UDP syslog only, so that is what the receiver speaks. It is Windows-only because the headless install, firewall scoping, and watchdog are built around Task Scheduler and Windows Firewall.
